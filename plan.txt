Bước 7
Kiểm tra Free Space của Tablespaces của Oracle
COLUMN pct_free FORMAT 999.99 HEADING "% Free"
COLUMN name FORMAT A16 HEADING "Tablespace Name"
COLUMN mbytes FORMAT 99,999,999 HEADING "Total MBytes"
COLUMN used FORMAT 99,999,999 HEADING "Used Mbytes"
COLUMN free FORMAT 99,999,999 HEADING "Free Mbytes"
BREAK ON REPORT
COMPUTE SUM OF mbytes ON REPORT
COMPUTE SUM OF free ON REPORT
COMPUTE SUM OF used ON REPORT
SELECT
fs.tablespace_name name,
df.totalspace mbytes,
(df.totalspace - fs.freespace) used,fs.freespace free,
100 * (fs.freespace / df.totalspace) pct_free
FROM
(SELECT
tablespace_name,
ROUND(SUM(bytes) / 1048576) TotalSpace
FROM
dba_data_files
GROUP BY
tablespace_name
) df,
(SELECT
tablespace_name,
ROUND(SUM(bytes) / 1048576) FreeSpace
FROM
dba_free_space
GROUP BY
tablespace_name
) fs
WHERE
df.tablespace_name = fs.tablespace_name(+);
Copy toàn bộ vào Secure CRT.
Thực hiện trên 1 máy

Kiểm tra các unusable indexes
select  ' alter index '||owner || '.' || index_name ||  ' rebuild ; '
  from dba_indexes where STATUS  = 'UNUSABLE'
   union all
      select  ' alter index '||INDEX_OWNER || '.' || index_name ||  ' rebuild  partition ' ||partition_name || '; '
         from dba_ind_partitions where STATUS  = 'UNUSABLE'
          union all
             select  ' alter index '||INDEX_OWNER || '.' || index_name ||  ' rebuild  subpartition ' ||subpartition_name || '; '
                from dba_ind_subpartitions where STATUS  = 'UNUSABLE';

1. TỔNG QUAN DỰ ÁN
1.1 Bối cảnh và Vấn đề
Hệ thống SIMO hiện đang vận hành một hạ tầng công nghệ thông tin phức tạp bao gồm cơ sở dữ liệu Oracle RAC, MongoDB Cluster, Hadoop Cluster và nhiều ứng dụng quan trọng (WSO2, HAProxy, Kafka, Application Servers). Mỗi ngày làm việc, đội ngũ vận hành phải thực hiện kiểm tra đầu ngày (Daily Check) theo một kịch bản thủ công với hơn 20 bước kiểm tra trên nhiều máy chủ khác nhau.

Quy trình hiện tại có các hạn chế sau:
Tốn nhiều thời gian: 5-10 phút/database, nhân với nhiều hệ thống, tổng thời gian lên đến 45-60 phút mỗi sáng
Dễ bỏ sót: thực hiện thủ công dễ dẫn đến việc bỏ qua một số bước kiểm tra
Phụ thuộc vào con người: khi nhân sự vắng mặt, quy trình kiểm tra có thể bị gián đoạn
Thiếu lịch sử: không có dữ liệu lịch sử để phân tích xu hướng và cảnh báo sớm
Chậm trễ phát hiện sự cố: chỉ phát hiện vào 08:00 sáng thay vì liên tục

1.2 Mục tiêu Dự án
Xây dựng hệ thống tự động hóa hoàn toàn quy trình Daily Check của hệ thống SIMO với các mục tiêu cụ thể:
Tự động hóa 100% các bước kiểm tra thủ công được mô tả trong kịch bản Daily Check
Chạy tự động lúc 08:00 mỗi ngày làm việc và gửi báo cáo kết quả
Cảnh báo tức thời qua email/chat khi phát hiện bất thường
Lưu trữ lịch sử kết quả kiểm tra để phân tích xu hướng

2. KIẾN TRÚC ỨNG DỤNG
2.1 Kiến trúc Tổng thể
Hệ thống được thiết kế theo mô hình kiến trúc phân lớp (Layered Architecture) với các thành phần chính:

🖥️  PRESENTATION LAYER – Dashboard & Báo cáo
   Web Dashboard (Grafana/Flask)  |  Email Report  |  Alert Notification (Slack/Teams)
⚙️  APPLICATION LAYER – Core Logic
   Scheduler (APScheduler)  |  Check Engine  |  Alert Manager  |  Report Generator
🔌  CONNECTOR LAYER – Kết nối Hệ thống
   SSH Connector  |  Oracle Connector  |  MongoDB Connector  |  Hadoop Connector
🗄️  DATA LAYER – Lưu trữ Kết quả
   PostgreSQL (History DB)  |  Log Files  |  Config Store (YAML/Vault)
🏗️  INFRASTRUCTURE – Mục tiêu kiểm tra
   Oracle RAC DB  |  MongoDB Cluster  |  Hadoop Cluster  |  WSO2/HAProxy/Kafka/App

2.2 Luồng Xử lý
08:00: Check Engine bắt đầu chạy song song các kiểm tra trên tất cả hệ thống
Mỗi check module kết nối SSH tới máy chủ mục tiêu, thực thi lệnh và phân tích kết quả
Kết quả được so sánh với ngưỡng chuẩn (threshold) được cấu hình sẵn
Alert Manager gửi cảnh báo ngay nếu có bất thường (không chờ đến cuối)
Report Generator tạo báo cáo tổng hợp và gửi email lúc khoảng 08:15
Kết quả được lưu vào database lịch sử để phân tích xu hướng

2.3 Các Module Kiểm tra
Oracle Database Module (11 checks)
Bước 1: Kiểm tra date/hostname – xác nhận kết nối đúng máy chủ
Bước 2: Kiểm tra phân vùng đĩa – df -k, cảnh báo nếu %used >= 90%
Bước 3: Kiểm tra CRS status – crs_stat -t, xác nhận ONLINE/OFFLINE đúng quy định
Bước 4: Kiểm tra OCR – ocrcheck, xác nhận integrity check succeeded
Bước 5: Kiểm tra Voting Disk – crsctl query css votedisk, xác nhận 3 disk ONLINE
Bước 6: Kiểm tra Archive Switch – sqlplus, alter system archive log current
Bước 7: Kiểm tra Free Tablespace – SQL query, cảnh báo nếu %Free dưới ngưỡng
Bước 8: Kiểm tra Unusable Indexes – trả về no rows selected là bình thường
Bước 9: Kiểm tra Invalid Objects – trả về no rows selected là bình thường
Bước 10: Kiểm tra ASM Disk Group – %used phải nhỏ hơn 90%
Bước 11: Kiểm tra Alert Log – grep ORA-/TNS-/Errors trong 1000 dòng cuối
MongoDB Module (3 checks)
Bước 1: Kiểm tra date/hostname trên cả 2 node (10.1.36.41 và 10.1.36.44)
Bước 2: Kiểm tra phân vùng đĩa – df -kh, %used < 90%
Bước 3: Kiểm tra trạng thái service – systemctl status mongod
Hadoop Module (3 checks)
Bước 1: Kiểm tra date/hostname trên 3 node (10.1.36.31/34/37)
Bước 2: Kiểm tra phân vùng đĩa – df -kh
Bước 3: Kiểm tra HDFS – hdfs dfsadmin -report, xác nhận Live DataNode
Application Module (5 ứng dụng x 3 checks)
WSO2 EI Cluster (10.1.46.31/32): systemctl status wso2am-3.2.0.service
WSO2 APIM Cluster (10.1.16.11/12): systemctl status wso2am-3.2.0.service
HAProxy (10.1.16.17/18): systemctl status haproxy
Kafka (10.1.46.23/24): systemctl status kafka
Application Server (10.1.46.41/42/43): systemctl status + docker container check
